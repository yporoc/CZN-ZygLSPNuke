# ============================================================================
# ZygNuke v7 流量规则 — 抗更新 / 多层抗性设计  (generated 2026-11-20)
# ============================================================================
# 设计哲学（重要，先读）：
#   反作弊主防线在 native + Java 层（库不映射 / JNI 桩 / 埋点 no-op），
#   本规则文件是【纵深防御第二层】，用于拦截"万一底层失效"时漏出的端点与埋点。
#   因此大量使用【内容特征(regexi/ascii)】而非仅域名——SDK 换域名只要路径/参数
#   还叫 DSDUC / token/req / stove_security 仍会被拦（抗更新核心）。
#
# 语法：ACTION DIRECTION MATCHTYPE [value]
#   ACTION: LOG(记录不干预) | PASS(同LOG) | HIDE(仅隐藏日志不碰包)
#           DROP(真阻断: W=跳过发送 / R=清空已读内容,长度守恒不杀连接)
#   DIRECTION: W(上行) | R(下行) | B(双向)
#   MATCHTYPE:
#     any                  全部命中
#     hosteq <host>        Host 头完整精确匹配(忽略大小写/端口) [抗子串误伤]
#     hostfull <bytes>     整包字节精确相等
#     host <substr>        Host 子串(大小写不敏感, 旧版兼容, 可能误匹配)
#     ascii <substr>       原始明文字节子串(大小写敏感)
#     regexi <ERE>         POSIX ERE 正则, 大小写不敏感
#     regex <ERE>          POSIX ERE 正则, 大小写敏感
#     hex <hex bytes>      十六进制字节序列
#     len <min-max>        包长范围
#     wsop <n>             WebSocket opcode(帧首字节低4位)
#     entropy <0-8>        香农熵下限(密文块识别)
#   DEFAULT W/R DROP|HIDE  设置某方向默认动作
# 优先级：显式命中 > 默认；显式间 DROP(3) > HIDE(2) > LOG/PASS(1)。
# 热重载：保存后约 15s 自动生效，无需重启游戏（双缓冲原子切换）。
# ============================================================================

# --- 基线：全量记录上下行明文，零干预（最安全；DEBUG/取证用）----------------
LOG B any

# ---------------------------------------------------------------------------
# 第一组：反作弊网络端点 —— 内容特征为主（抗域名更换）
# 关键：即使 SDK 把域名从 mgs.smilegate.com 换成新域名，只要请求路径/参数
#       仍含这些特征词，就命中。这是抗更新的核心。
# ---------------------------------------------------------------------------
DROP W regexi (DSDUC|token/req|mgs-t\.playstove\.com|api/token|RH012|verifybypass|gcs/query|rh[a-z_]*core[/.])
DROP B hosteq mgs.smilegate.com

# ---------------------------------------------------------------------------
# 第二组：反作弊生命周期埋点 —— 网络层兜底（抗 Java hook 失效）
# analyticvoid(LSPosed) 已在 Java 层 no-op 这 6 个事件；此条是第二层：
# 若某次更新绕过了 Java hook，只要事件名还叫 stove_security* ，
# 上行到 Singular 时仍被真阻断。hemi 双向，R 方向若回显也被清。
# ---------------------------------------------------------------------------
DROP B ascii stove_security

# ---------------------------------------------------------------------------
# 第三组：下行(R)反作弊响应清洗 —— 上下行平等处理（v7 能力）
# 注意：HDR 只在请求里，下行无 Host 头，故下行用"内容特征"匹配。
# 当前源头已断(库不映射)，下行命中=0；这是布防，命中即清空 buffer 使
# 上层解析失败，但返回长度守恒 → 连接不破、游戏不掉线。
# 保守仅列高置信特征，避免误伤游戏正常 JSON 响应。
# ---------------------------------------------------------------------------
DROP R regexi (RH_VM_CONFIG|"vm_auth"|"anti_cheat_result"|DSDUC_RESP)
# 如需观察下行而不阻断，把上面一条改成：LOG R regexi (...)

# ---------------------------------------------------------------------------
# 第四组：高熵密文块标记（仅记录，用于发现新端点，不阻断）
# 反向利用：若出现未知加密通道，日志里会显出高熵帧，便于追加精确规则。
# ---------------------------------------------------------------------------
LOG B entropy 7.5

# ---------------------------------------------------------------------------
# 安全与抗性说明（务必遵守）
#   1) 绝不要用 `DROP B any` / `DEFAULT W DROP` —— 会阻断账号/主协议导致掉线。
#      默认 LOG + 精确 DROP 是"误伤面最小"的抗性设计。
#   2) hosteq 优先于 host：hosteq 完整匹配，杜绝 `not-mgs.smilegate.com.evil.com`
#      这类子串误伤。
#   3) 抗更新：底层 mock/native 桩不依赖规则；规则也以内容特征(regexi)为主，
#      SDK 改域名/改 IP 仍可拦；只有路径+域名全换才需追加新特征。
#   4) 双向：W 真阻断(不发送)；R 真阻断(清空已读,长度守恒)。HIDE 只隐藏日志。
#   5) 验证过的真实流量(11 Host: api.onstove/facebook/singular/游戏主协议...)
#      对本规则零误伤；唯一命中是历史存档的 stove_security(本次为0)。
#   6) 规则文件缺失时模块自动生成安全 LOG-all 模板（绝不默认阻断）。
